# Модель вероятности неплатежа эмитентов облигаций РФ (PD на 6 месяцев)

Инструмент инвестиционных рекомендаций. По отчётности, котировкам облигаций и рейтингам он оценивает
вероятность того, что эмитент не заплатит по облигациям в ближайшие 6 месяцев. Сравнивает MARS с моделью
Альтмана и предлагает долю капитала. Что изменено по рецензии — в [CHANGES.md](CHANGES.md).

## Запуск

```bash
pip install -r requirements.txt
python -m pytest -q tests           # 20 автотестов, ~2 мин
python collect_moex.py              # эмитенты, выпуски (включая погашенные), котировки — MOEX ISS
python collect_girbo.py             # годовая РСБУ — ГИР БО ФНС (bo.nalog.gov.ru)
python build_dataset.py             # панель «эмитент × квартал», метки, сводки покрытия
python train.py                     # обучение, сравнение, отчёт models/report.txt
streamlit run app.py                # интерфейс
```
Или `run_all.bat` / `bash run_all.sh`. Сборщики можно перезапускать: скачанное не перекачивается,
а сбои (status=error в журнале) повторяются. Чтобы метки воспроизводились, закрепите дату выгрузки:
`set PD_AS_OF=2026-11-20` (Windows) или `export PD_AS_OF=2026-11-20`.

## Целевая переменная

**Цель (основная, `TARGET_MODE = "broad"`):** событие неплатежа — техническая просрочка или дефолт — по
облигациям эмитента в интервале (t, t + 6 мес.], где t — конец квартала. Эпизод TD → D считается одним
событием с датой первого неплатежа. Режим `strict` — только полноценный дефолт. Одно и то же
определение используется в базе, отчёте и интерфейсе.

Правила разметки:
* метка ставится, только если окно целиком внутри периода полного покрытия реестра (с 01.01.2024)
  и уже закончилось к дате выгрузки. Иначе статус `unknown_no_coverage` / `unknown_open_window`.
  События 2022–2023 годов в реестре есть, но выборочно — они идут только в признак «было событие за 12 мес.»;
* событие в день среза относится к прошлому, событие в последний день окна — к окну;
* после полноценного дефолта и до даты исправления (`cure_date`) эмитент из срезов исключается.
  После исправления срезы возобновляются. На текущую дату он показывается со статусом «в дефолте»;
* эмитент попадает в срез, только если у него есть выпуск в обращении на эту дату (в том числе погашенный позже).

Отчётность на дату t: только опубликованная до t. Если вышло исправление, берётся последняя версия,
опубликованная к t. Дата публикации — из источника, иначе консервативная оценка (годовая РСБУ — 31.12 + 120 дней,
промежуточная — + 60). Квартальные потоки пересчитываются в «последние 12 месяцев» (LTM), динамика —
к тому же периоду годом ранее того же стандарта и периметра. Пустая строка отчёта — пропуск, а не ноль.

## Модели и проверка

1. **Altman Z''** (развивающиеся рынки): Z'' = 3,25 + 6,56·X1 + 3,26·X2 + 6,72·X3 + 1,05·X4;
   зоны: > 5,85 — безопасная, 4,35–5,85 — серая, < 4,35 — бедствие. Вероятность — логит-калибровкой.
2. **Altman-логит** — те же X1–X4 с весами, оценёнными на российских данных.
3. **MARS (отчётность)** — коэффициенты и их динамика.
4. **Логит на входах полного MARS** — контроль: показывает, что даёт сама форма MARS.
5. **MARS (отчётность + рынок + рейтинги)** — основная модель.

MARS (Multivariate Adaptive Regression Splines) — своя реализация в `mars.py`: прямой проход с базисом
полного ранга, обратный отбор по GCV, логит сверху.

**Разбиение:** модель «обучена на дату» `TRAIN_DATE = 30.06.2025`. В обучение идут только срезы, у которых
окно закончилось к этой дате. Общий тест — срезы после неё с завершённым окном. Самолёт в обучение не
входит вовсе; его срезы до даты обучения показаны отдельно. Проверки разбиения выполняются автоматически и
попадают в отчёт. Метрики: покрытие, ROC AUC, Gini, KS, AP (average precision), Brier, калибровка.
Разница AUC оценивается бутстрэпом по эмитентам (кварталы одного эмитента пересэмплируются вместе),
отдельно — на подвыборке только отобранных компаний.

## Интерфейс

* **Облигация / эмитент** — быстрый выбор пяти обязательных компаний. Три даты раздельно: оценки,
  отчётности (период и публикация), котировки. Предупреждения о недостающих данных и доле подстановок.
  PD по моделям, рекомендация и пошаговый расчёт доли.
* **Скринер** — все эмитенты с датами данных и долей подстановок.
* **MARS vs Альтман** — метрики, ROC, калибровка, история Самолёта, состав выборки по периодам.
* **Своя отчётность** — пустое поле значит «нет данных». Можно подставить отчёт из базы и сравнить с оценкой в базе.

**Доля капитала** — половина критерия Келли, потолок 10%; при PD ≥ 50%, дефолте, отсутствии или
устаревании доходности — 0 или «расчёт недоступен» с причиной. LGD 70% применяется к любому событию
цели (консервативно). Ставка сравнения 16,5% — обновите в `config.py`. Упрощение: годовая YTM
переводится в полугодовую, цена реализации через полгода не моделируется.

## Ограничения

* **Квартальная отчётность.** Бесплатного API для квартальной РСБУ/МСФО нет. ГИР БО даёт годовую
  РСБУ. Квартальные данные вносятся в `financials_manual.csv` (из раскрытия эмитента или e-disclosure).
  Начать стоит с пяти обязательных компаний. Доля срезов с квартальной отчётностью видна в `coverage_report.csv`.
  Если для существенной части выборки есть только годовые данные, это нужно согласовать как отступление от ТЗ.
* **Совокупность эмитентов.** По умолчанию в выборке 100 отобранных компаний плюс эмитенты реестра. Последние
  попали в выборку из-за события, поэтому абсолютный PD завышен (сравните доли по `origin` в `models/periods.csv`).
  Честнее режим `PD_POPULATION=all` после `python collect_moex.py --population all` — все эмитенты
  корпоративных облигаций MOEX на дату среза, но это долго.
* **Реестр событий** собран по агрегатору; флаг `verified=1` — только у сверенных с первоисточником записей.
* Банки и страховщики не включены: у них другие формы отчётности.

`tests/make_fake_raw.py` генерирует синтетические данные только для проверки кода. Ухудшение перед
событием там заложено, поэтому метрики на этих данных ничего не говорят о качестве модели.
